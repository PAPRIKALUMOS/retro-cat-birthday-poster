# Revising an Existing Poster

Read this only when the user asks to change a poster that has already been generated or delivered. Do not run the full new-poster inspection; verify only the requested changes and the areas they touch.

## Choose the edit base

- Start from the last poster the user accepted or clearly referenced. If they ask to change the most recently delivered poster without rejecting it, that poster is the accepted base.
- For further corrections, use the best coherent working version that kept the earlier accepted improvements. Confirm which file you are editing before each image call; do not go back to an older draft just because it is easy to find.
- If the intended base is ambiguous, ask which poster to edit. A coherent improvement with one unresolved target is still a valid base (see the correction rules in `SKILL.md`).
- Look at the actual base before writing the brief. Derive every preserve statement from what is visible in it, not from earlier task history. The accepted poster's layout, text and marks are the truth: do not restore template defaults for unaffected content, and do not force the default two-band cake layout when the user has already customized it.
- Save the result as a new version when the host exposes file outputs; never overwrite the accepted base.

## Assign input roles

Label every image in attachment order and supply only what the change needs:

- `Image 1: current working poster - base to edit.`
- Do not attach the base template for an ordinary revision. Use it only when the user explicitly asks to restore a damaged protected element that cannot be rebuilt from the current poster, or, labeled `lettering style reference only`, when adding a headline to a poster that has none (its placeholder headline shows the style).
- Attach a cat photo (identity reference only) only when the change affects identity, markings, anatomy or photographic integration.
- For accessory changes, attach the selected set only when the current poster does not show the design clearly enough (changing the design, or a distorted, incomplete or obscured accessory). Use both parts when both are worn; if the cat keeps its own item in one spot, use the set only for the remaining party item. Never attach the whole directory.
- Label any other image as material, clothing or accessory, or background reference.

## Write a local edit brief

Send only a concise edit brief and the necessary labeled images: no conversation history, inspection notes, rejected prompts or this skill. Describe the requested final state against the current poster, drop superseded targets, and include the concrete treatment the changed area needs (the lettering specs and fixed blocks in `references/brief-template.md`, or Illustrated Additions in `SKILL.md`), not the whole new-poster brief.

```text
Asset: revised cat birthday poster; one image; keep the accepted ratio [or state the new ratio]

Input images:
Image 1 is the current working poster and the only base to edit.
[List only additional references that are necessary.]

Change:
[Only the user's requested change and its location.]

Preserve:
[Critical identity, character, composition, text, background and other unaffected details, as they appear in Image 1.]

Constraints:
Limit changes to the requested targets and the local contact or occlusion changes needed to complete them. Do not redesign unaffected areas or add unrelated subjects, wording, logos or scene elements.
```

Resolve the scope of a correction by the component the user names, even if they describe the defect loosely: "headline lettering" means the whole headline across every script, "cake name" means the lower-band name only. Check the named component, include every confirmed defect in the brief, and if the user only asks whether it meets the requirements, answer without an image call.

## Special revisions

- **Text:** update only the requested value using `references/text-rules.md`; for a lettering-style-only revision keep the resolved wording. State the resulting literal text and placement once:

  ```text
  Headline: [text, or none]
  Cake upper band: [text, or blank]
  Cake lower band: [text, or blank]
  ```
  Keep the layout of the accepted poster unless the user asks otherwise.
- **Candles:** `references/candles.md`.
- **Ratio:** treat it as a layout change, not a canvas extension. Keep the headline near the top, distribute added space on purpose, keep the protected art as one unstretched group, and leave no accidental empty band.
- **Accessories:** use the selected set only for the party item(s) the cat will wear, and keep every worn item photographic; include those items and their contact boundaries in the edit region; allow local fur, clothing and shadow changes needed for a believable fit while preserving identity and anatomy.

## Execute and verify

- Prefer a localized edit, and repeat the preserve list in every edit request (drift builds up silently across rounds).
- Compare the result with its base: check each requested target and the directly affected areas for drift. Preserve statements for later edits must reflect what actually succeeded.
- Apply the correction and checkpoint rules in `SKILL.md` Step 6 to unresolved targets. Do not resume correction plans from other tasks or fix issues outside the user's current request.
- Deliver as in Step 7, disclose any unresolved target and stop.
